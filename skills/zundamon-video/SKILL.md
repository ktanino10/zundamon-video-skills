# ずんだもん解説動画

## 最初に揃えるもの

会話から題材・対象視聴者・長さ・絵柄・口調・配置・成果物を読み取る。既に指定済みの内容を聞き直さない。新しい素材が届いたら、古い版と混同せず実filename/version/hashを残す。

出力は、台本、素材/音声の来歴、実WAV長から作った字幕/章、MP4、ポスター、確認記録を基本とする。公開は別の操作。

素材やツールが未確認なら、先に[権利と納品の確認](references/rights-and-delivery.md)を読む。MCP未接続の場合は[セットアップガイド](references/setup.md)を案内し、無断インストールやOS警告の回避はしない。

## 台本

- 「ボク」「〜なのだ」「〜のだ」を自然に使い、すべての文を機械的に同じ語尾へ置換しない。
- 専門用語・数値・否定・条件は変えない。仮定、未実測、模式図を事実や完成品へ昇格させない。
- 字幕と読み上げ文を分けてよい。読み上げ用のかな表記も元の意味へ対応させる。
- 章/cue IDを付け、新音声で時刻を再計算する。前版の長さをコピーしない。

## 音声は実MCP経由

1. 使用可能なnative MCP toolを発見しschemaを読む。既に読み込まれたtoolは既知schemaを使えるが、存在しないtoolを創作しない。
2. 実pingと実話者一覧を確認し、「ずんだもん/ノーマル」等の指定を名前/スタイルから解決する。IDを固定常識として扱わない。
3. 各生成で話者と話速を明示し、許可された出力rootの新規batchへ保存する。勝手な再生・辞書変更はしない。
4. 実tool名・引数・結果、Engine版、MCP実装identityの根拠、text/WAV hashと長さを対応させる。

MCP内部がEngine HTTP APIを呼ぶのは正常。エージェントが直接HTTPや別SDKで生成したものをnative MCP生成と呼ばない。MCPが使えなければ、未接続とEngine停止を区別し、欠けている接続だけを示す。既存音声を動きの仮確認に使う場合も、語調未反映・仮使用を明記する。

## 絵と動き

- 原PSD、ZIP、音声モデルは利用者の管理下に置き、成果の公開先へ自動コピーしない。
- 読めた実レイヤーだけを使う。merged画像の書出しと、口/目/腕の差分抽出は別の能力として記録する。
- `scripts/psd_layers.py`は限定的なPSDv1/RGB8/RLE/単純group用。実入力SHAを渡し、default合成を保存merged画像へ比較してから使う。未対応条件をignoreしない。
- マスク/効果/未知のformatで失敗したら、追加ツールの許可または利用者が出したPNG差分を求める。一般PSD処理系を際限なく自作しない。
- 音量連動なら`animation.py`のPCM RMSを使える。これは音素同期ではない。無音で閉口するか、実音声の区間で口が動くかを確認する。
- まばたきや身振りは説明を補助する程度にし、声の切れ目や章の意図へ結ぶ。演出の時間を実物の動作時間と混同しない。

## 配置

図・pin・字幕を主役にし、すべての使用poseの不透明領域がそれらへ重ならないようにする。

バストアップの切断面が画面内で浮く場合、短い切り抜きをさらに動かすのではなく、全身spriteを下端より下まで続けて配置するか、全身と足元を見せる。静止画だけでなく、口/腕/目の全状態と実encoded映像でも確認する。

## 出力と確認

保存は新しい版/filenameへ行う。以前のWAV/MP4、素材原本、source/receiptを上書きして来歴を消さない。

最低限、次を確認する：

- 指定した声/スタイルで実生成されたWAVの形式・hash・実長
- 新音声に対応した字幕・章の時刻、無音/境界での口状態
- 意図した身振りと、胴体・図・字幕の非重複
- MP4全decode、実player再生/seek、表示される音声/素材credit
- 旧版と非対象ファイルが保持されていること

聞いていなければ発音を人手確認済みと書かない。音量同期しかしていなければ音素同期と書かない。単一contextの検査を独立reviewやA/B比較と呼ばない。

最後は、実成果の場所・どこまで実施したか・残る不足を短く返す。動画完成やスキル利用を公開/uploadの承認へ広げない。
